**Breaking:** Langfuse credential discovery now reads one canonical, component-owned config block — `langfuse.host` plus `langfuse.projects.<project-name>.{public_key, secret_key, project_id}` — via the new single-source-of-truth reader `lifecycle/_langfuse_config.py`. Previously the two consumers disagreed: the chat trace proxy read nested `langfuse.projects.*` while `GET /fleet/langfuse` read a top-level `langfuse_projects`/`langfuse_base_url` pair. Neither shape was used by any deployed component, so both discovery paths silently returned nothing and `/chat/langfuse/projects` stayed empty. `FleetLangfuseProject` gains an optional `project_id`. There is deliberately no fallback to deploy-plane `LANGFUSE_*` environment variables or to any pre-standard config layout: a component that has not migrated reports no projects.
