The Langfuse proxy no longer forwards the upstream `Content-Encoding` header. It forwards the caller's `accept-encoding` upstream, so Langfuse replies gzipped — but httpx decompresses transparently, leaving a plain body labelled `Content-Encoding: gzip`. Any client that honours the header (httpx, requests) failed with a zlib `incorrect header check` on every `/chat/langfuse/{project}/traces` call, while curl — which does not ask for gzip — saw a healthy 200, making it look like an auth problem.
