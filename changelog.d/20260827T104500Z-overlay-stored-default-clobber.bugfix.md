`SystemSettingsStore.overlay` no longer discards a configured value when the stored setting is still its default. Every `SETTINGS_DEFAULTS` key was copied out of `system_settings.json` unconditionally, and because `SystemSettings` fills unset fields from those same defaults — and the store is seeded with a full key set on first boot — "stored" and "never touched" were indistinguishable. A `ghcr_pull_token` saved through the config panel therefore landed in `config.json`, was read straight back by that panel so it displayed as saved, and was then overwritten with the seeded empty string on every boot, leaving private GHCR pulls unauthenticated with no way to fix them from the surface that appeared to fix them. A stored value that still equals its default now yields to a configured one; a real stored value still wins.
