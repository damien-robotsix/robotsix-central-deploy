Removed every `ROBOTSIX_LIFECYCLE_*` environment variable from the docs, README, and tests. They have not been read since the robotsix_config migration — `LifecycleConfig` is a plain `BaseModel` and nothing in `src/` touches `os.environ` — but the docs still advertised 24 of them, so an operator following them configured nothing. `docs/lifecycle/configuration.md` now describes the actual mechanism (one JSON file located by `ROBOTSIX_CONFIG_FILE`, the settings-store overlay, and the self-contract seed) and points at the model and the committed schema for the field reference instead of restating them. A new guard, `tests/lifecycle/test_no_env_config_channel.py`, fails if any file names a concrete `ROBOTSIX_LIFECYCLE_<NAME>` variable again.
