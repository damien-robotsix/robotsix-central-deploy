FileStore now writes `lifecycle_state.yaml` atomically (temp file + fsync + `os.replace`) so an interrupted or concurrent write can no longer truncate it to zero bytes. A truncated state file previously parsed to `None` and crash-looped central-deploy startup, taking the whole gateway (and thus every `*.deploy.robotsix.net` route) down. `_load` also now self-heals a pre-existing empty/`None` state file by treating it as empty and re-seeding from the component registry instead of raising.
